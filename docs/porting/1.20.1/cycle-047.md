# Cycle 047 — migrate Forge 6.2 machine tanks and registry aliases

The packaged test starts with an actual Forge 1.20.1 world saved by Ender IO `6.2.18-beta`, the last release near the recorded historical branch tip. Both releases run on Forge `47.4.28` and Temurin `17.0.18`. The fixture script copies the closed source world into a separate installation and opens the copy twice with the port. Every launch is headless and uses an isolated working directory, loopback and the accepted server EULA. The two mod jars are the only mods in their respective profiles. [Team Ender IO release](https://github.com/Team-EnderIO/EnderIO/releases/tag/v6.2.18-beta) · [Official distribution](https://modrinth.com/mod/enderio/version/6.2.18-beta)

## Implementation

- Machine tanks read the 6.x `Fluid` root and indexed Forge stacks as well as the older single-stack layout. The current `Fluids` field takes precedence, including an explicitly empty tank. Conversion preserves fluid amounts, typed tags and saved entries outside the current tank layout. New saves write the current format.
- Explicit item and block aliases now also participate in Forge's `MissingMappingsEvent` when reopening registry snapshots. The ten historical Ender IO fluids have remaps for both source and flowing IDs. The packaged test verifies the renamed XP Juice ID, two renamed placed blocks and a renamed ingot in an inventory.
- The new native tank regression exercises both blocks, tagged contents, the two legacy layouts, out-of-layout entries, the unbound block-entity load path and native field precedence.

The build passed **78 ordinary JUnit and 411 native tests**. The native totals were 170 core, seven Mekanism, 115 main registry, 93 main gameplay and 26 addon tests. The packaged run passed **18 assertions** across the original server, first converted startup and converted restart. Each phase checks both tank stacks and seven diamonds per tank, both placed blocks, five ingots in a vanilla chest, and the alloy smelter's exact 1,250 FE, east pull mode, redstone control and alloying mode. Both 11,500 mB of tagged water and 21,750 mB of tagged XP Juice survived conversion and restart. All servers exited cleanly. Forge logged remaining missing IDs during the first conversion. The restart recorded zero ERROR/FATAL lines. The first fixture attempt established that 6.2 clamps the smelter's energy to zero without an installed capacitor. The final fixture installs the real capacitor before checking any migrated energy.

## Remaining migration work

A separate discovery world generated by the same old jar reproduced a chunk-load crash when the port tried to decode an old `ConduitBundle` with the later codec. This happens even for an empty legacy bundle. The converter needs to read the 6.x bundle and its saved graph, then prove populated connections, filters, upgrades, facades and routing against an actual old world. The source and copied crash fixtures are in `build/port-runtime/cycle-047-{legacy-discover,upgrade-discover}`. Their logs also identify unresolved registry IDs for legacy blocks, enchantments and items, including old conduit stacks. Migrating saved souls, paint, travel, machine tasks and carried tank items remains unverified. General 6.x world upgrades remain open.
